Modpoll WoT acquisition vocabulary 0.1

Namespace: https://top-maker.github.io/modpoll/vocab/wot-modbus#. This project extension describes ordered block reads and decoding. It is not a W3C standard. The W3C draft Modbus binding provides modv: entity, address, quantity and byte/word-order terms.

The independently versioned modpoll-wot package validates the executable profile. Its first preview supports Modbus only; it is not a general JSON-LD or WoT runtime. See the configuration documentation, extension schema 0.1 and complete contract 0.1.

modpoll:version
Root profile identifier, exactly the string 0.1.
modpoll:acquisition
Ordered array of physical block reads. Boundaries, gaps and order are preserved; no automatic coalescing.
modpoll:members
Ordered property mappings for a block. Every property has exactly one mapping; distinct aliases may share a backing address.
modpoll:property
Exact standard properties key, also used for output names.
modpoll:offset
Non-negative offset from block start. Register blocks count 16-bit registers; bit blocks count eight-bit groups. The block quantity still counts physical bits.
modpoll:dataType
Exact decoder type: int/uint16/32/64, float16/32/64, bool/bool8/bool16, or stringN (1–9999 bytes). Strings and numeric bit-table spans require complete requested bytes.
modpoll:bit
Optional register bit 0–15, allowed only with register bool; produces a scalar boolean.
modpoll:multiplier
Optional finite numeric multiplier or decimal string; multiplication, not division. Numeric values execute using existing float semantics. No string scaling or inverse-write transform.

Unknown executable fields are rejected. Contract 0.1 semantics remain fixed; new incompatible semantics require an explicit revision. Hosted vocabulary paths are preserved independently of the stable and preview documentation trees. Model validity does not establish device-map correctness or stock-client support for these extensions.
